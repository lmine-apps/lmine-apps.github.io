# かよママさん「あなたの台所を軽くする4日間」お試しWEBアプリ MVP

診断ファネルの後ろに挟む、4日間 × 1日3分の期間限定WEBアプリ。
「診断で気づく → 小さく試す → 自分で確かめる → コースを体験の延長として理解する」までを1つのアプリで完結させます。

---

## 1アプリ・4入口の仕組み

アプリ本体は **index.html 1つだけ**。診断結果ページから、URLの `?type=A/B/C/D` で表示内容が切り替わります。

### 入口URLの例

```
https://example.com/kayomama-trial-app/?type=A
https://example.com/kayomama-trial-app/?type=B
https://example.com/kayomama-trial-app/?type=C
https://example.com/kayomama-trial-app/?type=D
```

各診断結果ページ（LINE内のURL）に、それぞれ対応するURLを埋め込んで運用します。

### 内部管理コードは非表示

A/B/C/D は内部管理コードで、**画面には一切表示しません**。表示に使うのは以下の愛称のみ：

| 内部 | 表示名 |
|---|---|
| A | もっとうまく作りたい、遠慮しがち さん |
| B | 今日何にしよう、が口ぐせ さん |
| C | スマホ片手に、正解探し さん |
| D | もう回ってる、次いきたい さん |

## ローカルでの起動方法

`index.html` をブラウザで開くだけです。

```bash
# 例：Windowsのエクスプローラーからダブルクリック、または
# ローカルサーバで動かしたい場合（推奨）:
cd kayomama-trial-app
python -m http.server 8080
# → http://localhost:8080/?type=B などで動作確認
```

`?type=A` / `?type=B` / `?type=C` / `?type=D` を末尾に付けてください。

## `config.js` の編集方法

```js
window.APP_CONFIG = {
  appTitle: "あなたの台所を軽くする4日間",
  welcomeVideoUrl: "",                          // ← ウェルカム画面の動画
  offerVideoUrl: "",                            // ← 4日間終了後・レポート後・コース説明前の動画
  courseUrl: "https://example.com/course",      // ← マスターコース申込ページURL
  supportUrl: "",                                // ← 予備
  unlockIntervalHours: 24,                       // 通常モードの解放間隔（時間）
  appAvailableHours: 120,                        // アプリの有効期限（時間）
  testMode: false,                               // true にすると分単位で動く
  testUnlockIntervalMinutes: 1,                  // テスト時の解放間隔（分）
  testAppAvailableMinutes: 10,                   // テスト時の有効期限（分）
  storageKey: "kayomama_trial_v2"                // localStorage キー
};
```

### 動画URLの設定

**ウェルカム動画（`welcomeVideoUrl`）**
- 初回ウェルカム画面に表示される動画
- YouTube 埋め込みURL（`https://www.youtube.com/embed/xxxx`）または直接動画URL（`.mp4`）
- 空文字列 `""` の場合、動画枠自体が非表示

**オファー動画（`offerVideoUrl`）**
- 4日間を終えた方に向けたクロージング動画
- 表示位置：レポート → 「この続きの案内を読む」ボタン → **オファー画面 → タイプ別の接続文 → ここに動画（タイトル「4日間を終えたあなたへ」）→ コース説明 → 価格 → 外部コースページへのボタン**
- YouTube 埋め込みURL または直接動画URL（`.mp4`）に対応
- 空文字列 `""` の場合、動画タイトル・枠とも一切表示されません
- 既存の `video-wrap` クラスを再利用しています

### コース申込ページURLの設定

- `courseUrl` を実際の申込ページURLに差し替え
- 「家庭料理マスターコースを詳しく見る」ボタンから別タブで開きます
- **重要**：4日間の途中では一切表示されません。到達動線は「4日間完了 → レポート閲覧 → 続きの案内 → オファー画面」に限定されています。

## `content.js` の編集方法

タイプ別の文章はすべてこのファイルに集約されています。テキストの校正はここだけ触れば済みます。

構造：

```js
window.TYPE_CONTENT = {
  A: { displayName, intro, themeIntro, day1, day2, day3, day4, report, offerBridge },
  B: { ... },
  C: { ... },
  D: { ... }
};
```

各日の中身：
- `theme` … 画面上部の小見出し
- `body` … 説明本文（1〜2分で読める分量）
- `questions` … 質問配列
- `complete` … 完了時のメッセージ

## 解放条件（重要）

各日は **「時間経過」＋「前日完了」** の両方を満たしたときに開放されます。時間が経っていても、前の日が未完了の場合は開きません（「前の日を終えると開きます」と表示）。

- 1日目：開始直後に利用可能
- 2日目：開始から24時間経過 **かつ** 1日目完了
- 3日目：開始から48時間経過 **かつ** 2日目完了
- 4日目：開始から72時間経過 **かつ** 3日目完了
- 台所レポート：4日目完了後に閲覧可能
- **オファー画面：4日目完了＋レポート生成後のみ**（途中導線なし）
- 有効期限：120時間（5日）
- 完了済みの日は、期限内であればいつでも再閲覧可能

## モード切替

### 通常モード

上記「解放条件」に従って動作します。

### テストモード

`config.js` で `testMode: true` に切り替えると：
- 1分ごとに次の日が自動解放
- 有効期限は10分（デフォルト）

動作確認用途以外では `false` にしてください。

### debugモード

URL末尾に `?debug=1` を付けると、画面最下部に開発メニューが表示されます。

例：
```
?type=B&debug=1
```

できること：
- 保存データをリセット
- A/B/C/D で強制初期化（開始日時も現在にセット）
- 各日を完了扱いにする
- 現在のtype・モードを表示

**通常利用者には絶対に見せないでください。**

## localStorage の仕様

保存キー：`kayomama_trial_v2`（`config.js` で変更可）

保存内容：

```js
{
  version: 2,
  assignedType: "B",       // A/B/C/D（開始ボタン押下時に確定）
  startedAt: "2026-07-27T...",
  lastVisitedAt: "...",
  completedDays: { day1: false, day2: false, day3: false, day4: false },
  answers: { day1: {}, day2: {}, day3: {}, day4: {} },
  cardCreated: false,
  reportGenerated: false,   // 4日目完了時にレポートが生成された
  reportViewed: false,      // レポート画面を実際に閲覧した（進捗5/5達成条件）
  offerViewed: false,
  offerClicked: false
}
```

### `reportGenerated` と `reportViewed` の違い

- `reportGenerated`：4日目完了時にレポートが生成されるとtrue（オファー到達条件のひとつ）
- `reportViewed`：レポート画面を実際に開いた時点でtrue（進捗5/5の達成条件）
- この2つは別状態として管理されます

### タイプ保持ルール

- **タイプは「4日間を始める」ボタンを押した時点で確定**され、以後 **上書きされません**
- URLでの `?type=X` は「開始前」のみメモリ上で保持（pendingType）
- 開始前に別タイプURLを開き直すと、そのURLのタイプでウェルカム画面が表示されます
- **開始後は別タイプURLで開いてもタイプは変わりません**（「すでに開始している4日間があります」表示）
- URL に type がなくても、保存済みタイプで再開できます
- 不正な type（例：`?type=X`）を勝手にAへ振り分けません → 案内画面を表示

### データリセット方法

- ユーザー側：ブラウザの localStorage をクリア
- 開発者：`?debug=1` の開発メニューから「reset」ボタン

## 進捗表示（0/5〜5/5）

分子・分母には **5工程** のみを含めます。**診断完了は表示するが数えません**。

- 0/5：開始直後
- 1/5：1日目完了
- 4/5：4日目完了（レポート未閲覧）
- 5/5：台所レポートを閲覧した時点

## 必須回答について

`content.js` の質問に `required: true` を設定すると必須になります。未回答のまま「完了」を押すと、その質問の直下に穏やかなインラインエラーが表示され、最初の未回答項目までスクロールしてフォーカスします。**通常利用中に `window.alert()` は表示されません**（debug モード内のみ従来通り alert/confirm を使用）。

必須：
- 1日目の中心質問
- 2日目の中心質問
- Bの2日目「定番3つ」（3つとも）
- 4日目「変化を感じたか」「続けたら起きそうな変化」「次に身につけたいこと」
- 「その他」を選んだ場合の詳細入力

任意：
- 自由記述、自分への一言、補足説明、その他の詳細入力（「その他」以外）

### 「今日は料理をしなかった」への配慮

A・Cの一部の質問には「今日は料理をしなかった」という選択肢があり、選ぶと代替質問（最近作った料理・最近よかったと思えたこと 等）が表示されます。料理をしなかったことを理由にアプリを進められなくなることはありません。

### Cの2日目「料理名」

Cの2日目冒頭に「今日、または直近で作った料理は何ですか？」の短文入力があります（任意）。入力すると、3日目の「うちの味の物差し」カードと台所レポートに反映されます。

## 有効期限後の挙動

- 開始から120時間経過すると、未完了内容の入力・完了はロック
- **カード**と**レポート**は引き続き閲覧可能
- 4日間完了＋レポート生成が済んでいる方には、「この続きの案内を読む」ボタンからオファー画面へ進めます（未達の方にはボタン自体を出しません）

## 本番公開時の注意点

### 現状の制約（MVP）

このMVPは **端末ローカル時刻**と **localStorage** を使用しています。以下の制約があります：

- 端末の時刻を書き換えられると、期限判定を回避できてしまう
- 同じ人が別デバイスから開始すると、進捗が引き継がれない
- ブラウザの localStorage をクリアされると、進捗が消える

### 本番移行時に検討したいこと

- **サーバー時刻管理**：Cloudflare Workers や Supabase Edge Functions で時刻検証
- **署名付きトークンURL**：URLに含める `type` を改ざんできないようHMAC等で署名
- **Supabase / Firebase**：ユーザー進捗をクラウド保存 → クロスデバイス対応
- **LINE Messaging API連携**：診断結果からLINE友だち追加時に、公式アカウントのタグ付けを行い、そのタグをアプリで参照
- **購入済み判定**：マスターコース申込みAPIと連携して、購入後はコース案内を「継続支援」表示に切替

## LINE連携用イベント一覧

`app.js` の `trackEvent()` 関数で発火します。MVPでは console 出力のみ。本番では fetch 等でLINE Messaging APIやスプシに送信できます。

| イベント名 | 発火タイミング |
|---|---|
| `app_viewed` | ウェルカム画面を初回表示 |
| `app_started` | 「4日間を始める」ボタン押下 |
| `day1_completed` | 1日目 完了 |
| `day2_completed` | 2日目 完了 |
| `card_created` | 3日目 完了時（カード生成） |
| `day4_completed` | 4日目 完了 |
| `report_generated` | 台所レポート生成 |
| `offer_viewed` | コース案内画面を初回表示 |
| `offer_clicked` | 「マスターコースを詳しく見る」ボタン押下 |
| `app_expired` | 有効期限を過ぎた状態でホームを開いた |

すべてのイベントに `type: 'A' | 'B' | 'C' | 'D'` が付きます。

## アプリの目的（改めて）

このアプリは、無料講座を視聴する場所ではありません。

**役割**は次の5つに絞られています：

1. 自分の料理のパターンに気づく
2. 小さな行動を実際に試す
3. 自分専用のカードを作る
4. 変化を自分で言語化する
5. マスターコースを「体験の延長」として理解する

長文の教育コンテンツではなく、**1日3分の実践**で、本人が変化を言語化する場所です。
